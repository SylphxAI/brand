# Voice

**Precise, plain, and calm.** Sylphx is infrastructure people trust with their
data; the words sound like a good specification written by someone who has
run the system at 3 a.m.

1. **Concrete over clever.** Name the thing, the action and the result:
   "Database `main` restored to 14:02 UTC", not "Time travel, done."
2. **State facts; never defend them.** No "honest", "truly", "no fake". A
   status is Available, Preview or Planned; a number carries its unit.
3. **Every error says what happened and what to do next**, in one sentence
   each, with the request id to copy.
4. **Short sentences, sentence case, no exclamation marks.** Humour is rare,
   dry and never in errors or billing.
5. **Customer words, not ours.** No internal terms (Kernel, Cell, Hands,
   Release internals) on a public surface.
6. **Every number and claim is true and sourced.** Counts and statuses come
   from the product registry, prices from the live price catalog, speed only
   from a measurement. Never invent a certification, benchmark, customer or
   quote.

## Lines

- **Tagline:** *The backend your agents can run.*
- **Description (one line, every listing):** *Sylphx is one platform for
  hosting, data, auth, workflows and AI: one API, one key and one bill,
  provisioned by a person or an agent in one call.*

## Samples

- **Changelog:** *Database branches now start in under a second. A branch
  shares storage with its parent, so it costs only what changes.*
- **Error:** *This key can't create databases. Ask an owner of `acme` to add
  the `data:write` scope, or use a key that has it. Request `req_8f2k…`*
- **Empty state:** *No databases yet. A database is serverless Postgres that
  branches with your code.* [Create database] `sylphx data databases create main`
